description: 끝난 실험을 결과 JSON → 연구 일지 → 슬라이드 → 덱 → 백업 한 흐름으로 정리한다
argument-hint: [실험 이름이나 결과 파일 경로]
---

끝난 실험을 연구 기록으로 정리한다. 대상: $ARGUMENTS

CLAUDE.md의 "연구 기록"과 "결과 보고 기준"을 따른다. 아래 순서대로 하고, 각 단계의 결과를 짧게 보고한다.

1. **결과 파일 확인.** 이 실험의 결과 JSON이 `results/<주제>/`에 있는지 본다. `runs/` 아래에만 있으면
   `results/`로 복사한다(원본은 두고, 옮기지 않는다). 결과가 아직 없으면 어떤 스크립트로 만들지 말하고 멈춘다.
2. **판정 초안.** 결과 JSON에서 숫자를 읽어 판정 문장 초안을 쓴다. 표에는 완주·표본 수 같은 근거 열을 넣고,
   비교는 같은 시드끼리 짝지은 결과를 쓰며, "가장 좋다"는 어느 지표·어느 조건에서인지 적는다.
   확인되지 않은 원인 설명은 "가설"이라고 쓴다.
3. **비판적 검토.** `critic` 에이전트(없으면 general-purpose 에이전트에 같은 역할을 지시)에 초안, 데이터 파일 경로,
   주장 목록을 보내 근거 없는 비약, 과장·일반화, 빠진 단서·반례, 수정 문장을 받는다. 지적을 반영한다.
4. **연구 일지.** `docs/RESEARCH_LOG.md`에 실험 한 항목을 쓴다. 항목 형식은 그 파일 머리의 틀을 따른다
   (날짜, 질문, 설정, 결과 파일, 판정(검토 반영), 슬라이드, 다음 후보, 검토에서 고친 점).
5. **슬라이드.** `docs/deck_src/build_deck_plain.py`에 이 실험의 슬라이드(또는 기존 슬라이드 갱신)를 더한다.
   숫자는 `results/`의 JSON에서 읽고 코드에 손으로 적지 않는다. 문장은 소리 내어 읽기 쉬운 쉬운 말로 쓴다.
6. **덱 빌드와 확인.** 다음을 돌린다.
   ```
   /home/bong/anaconda3/envs/horcrux/bin/python docs/deck_src/build_deck_plain.py docs/deck_src
   ```
   pptx 스킬의 `validate.py --original docs/PPT샘플.pptx`로 검증하고, LibreOffice로 PDF 변환 뒤 바뀐 슬라이드만
   이미지로 렌더해 글자 넘침·겹침을 눈으로 확인한다. 문제가 있으면 고치고 다시 만든다.
7. **기록과 백업.** `CLAUDE_CHANGES.md`에 항목을 쓰고, `scripts/backup_to_disk.sh`를 돌려 결과와 덱을 백업한다
   (백업 디스크가 마운트돼 있지 않으면 그 사실만 보고한다).
8. **보고.** 사용자에게 판정, 표, 슬라이드 번호, 결과 파일 경로, "검토에서 고친 점"을 쉬운 문장으로 보고한다.
