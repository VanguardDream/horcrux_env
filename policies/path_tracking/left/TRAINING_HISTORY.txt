2. 보관 구조와 정책 계보
-----------------------

00_aborted_transfer_diagnostic/   전진 정책을 이용한 전이 실험, 의도적으로 중단
01_left_from_scratch_long/         새 정책과 새 VecNormalize로 시작한 좌측 Stage 1
02_left_continue_stage2/           01 final에서 연속 학습
03_left_continue_stage3/           02 final에서 안정화 연속 학습

성공한 정책 계보:

  01_left_from_scratch_long/final
    -> 02_left_continue_stage2/final
    -> 03_left_continue_stage3/best 또는 final

00은 성공 계보에 포함되지 않는다. 각 화살표는 왼쪽 run의 final_model.zip과
같은 run의 vecnormalize.pkl을 함께 불러와 reset_num_timesteps=False로 추가
학습했음을 의미한다.

각 번호 디렉터리는 정책만 추출한 복사본이 아니라 원래의 timestamped run 전체를
runs/에서 이동한 것이다. 모델, 정규화 통계, 평가, 체크포인트, 영상, TensorBoard,
monitor CSV, resolved config, metadata를 모두 보존한다.

4. 각 run 디렉터리의 파일 의미
--------------------------------

evaluation/best_model.zip:
  해당 run에서 가장 높은 평균 평가 리턴을 기록한 정책.

evaluation/best_model_vecnormalize.pkl:
  best_model.zip 저장 시점의 observation 정규화 통계.

evaluation/evaluations.npz:
  평가 timestep, episode return, episode length 원본 기록.

final_model.zip + vecnormalize.pkl:
  run의 마지막 정책과 그 시점의 observation 정규화 통계.

checkpoints/:
  주기별 정책 ZIP과 각 시점의 VecNormalize PKL.

videos/:
  학습 중 callback으로 녹화한 정책 실행 영상.

tensorboard/:
  PPO, rollout, 속도, 방향, yaw, 보상 지표의 TensorBoard 이벤트.

monitor/:
  8개 병렬 환경의 episode monitor CSV.

resolved_config.yaml / metadata.json:
  실제 실행 설정과 실행 시점의 Git/Python/패키지 정보. resolved_config 내부의
  resume 경로는 학습 당시 경로를 역사 기록으로 보존하므로 이동 후 경로와 다를 수 있다.


5. 확인 명령
------------

전체 좌측 학습 로그:
  tensorboard --logdir .\policies\path_tracking\left --port 6006

대표 정책 평가 예시:
  python training/evaluate.py `
    .\policies\path_tracking\left\03_left_continue_stage3\evaluation\best_model.zip `
    --vecnormalize .\policies\path_tracking\left\03_left_continue_stage3\evaluation\best_model_vecnormalize.pkl

결정론적 평가 episode가 같은 초기 조건과 seed를 사용하면 결과가 거의 동일할 수 있다.
현재 성능 수치는 학습 비교에는 유효하지만 강건성·일반화까지 증명하지는 않는다.
